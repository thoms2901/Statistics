Caesar cipher vs toy ECC: encryption and cryptanalysis

November 2026

I encrypt the same short message with two schemes: the toy elliptic curve scheme (secp256k1 with a small private key) and the Caesar cipher. Then I try to break both: Caesar with the letter statistics of English, the toy ECC by searching its small key space.

1. The toy ECC scheme

HW1 used the equation y² = x³ + 7 over the prime 17 to show how Q = kG works. Here the curve is the real secp256k1 (same equation, p ≈ 2256, group order n ≈ 2256, the code is the one of HW2), and the only toy element is the private key: k is drawn uniformly from 1..2b with b small. Elliptic curves do not encrypt data directly, so the scheme is a minimal hybrid (ECIES without the MAC):

key generation (receiver) private key k uniform in [1, 2^b] (toy: b = 8..36; real: [1, n-1]) public key Q = kG encryption (sender knows only Q) r uniform in [1, n-1] fresh ephemeral secret R = rG sent with the ciphertext S = rQ shared point keystream = SHA-256(x_S || 0) || SHA-256(x_S || 1) || ... c = UTF-8(message) XOR keystream ciphertext = (R, c) decryption (receiver knows k) S = kR = k(rG) = r(kG) = rQ same point as the sender message = c XOR keystream(x_S)

Role of the keys. The public key Q is used by the sender to encrypt; the private key k is needed by the receiver to decrypt. The sender also picks a random r for every message and throws it away after use. Both sides end up with the same point S, and the message is XORed with a keystream derived from S. Someone who only sees Q, R and c would have to find k from Q (or r from R), which is the discrete logarithm problem.

2. The Caesar cipher

Each letter is moved forward by a fixed number of positions in the alphabet: Es(x) = (x + s) mod 26, Ds(y) = (y − s) mod 26, with letters numbered A = 0 .. Z = 25. Case, spaces and punctuation are kept. The key s is the shift, 0..25, and s = 0 is the identity, so there are 25 useful keys.

3. Similarities and differences

Caesar toy ECC (hybrid)
type symmetric: the same s encrypts and decrypts, it must be shared in advance asymmetric: Q encrypts, only k decrypts, nothing shared in advance
encryption add s to every letter mod 26 pick r, compute R = rG and S = rQ, XOR the bytes with a keystream from S
decryption subtract s mod 26, the inverse of the same operation recompute S = kR with the private key, same XOR
underlying structure the group Z26 under addition the group of points of secp256k1 under point addition (order n ≈ 2256)
key space 26 (25 useful), about 4.7 bits toy: 2b (b bits); real: n − 1 ≈ 2256
determinism deterministic: same message, same ciphertext randomised by r: the same message gives a different ciphertext every time
what the ciphertext leaks everything except the shift: letter frequencies, word lengths, repeated words, index of coincidence only the length; the bytes are indistinguishable from uniform
what an attack needs some ciphertext and a model of the language only the public key Q (no ciphertext at all), and a small key space

In both schemes the secret is used in a group operation (adding s mod 26, multiplying a point by k), and decryption undoes it. The important difference for statistics: Caesar replaces each letter with another fixed letter, so the letter frequencies of the plaintext are still there, only shifted. The ECC scheme XORs the message with a pseudo-random keystream, so the ciphertext bytes look uniform whatever the message is.

4. Statistical cryptanalysis of Caesar

Corpus and language model

The reference distribution comes from eight public-domain novels from Project Gutenberg (Austen, Chesterton, Melville, Edgeworth), letters only. From the same corpus I also take the log-probabilities of all 676 bigrams and 17576 trigrams. Test plaintexts are drawn from Alice in Wonderland, which is not in the training set, so the attack is evaluated on unseen text. The Python script that builds the tables is in hw3/tools/build_corpus.py.

The algorithm

Let Oj be the count of letter j in a ciphertext of N letters and pi the corpus frequency of letter i. If the key is s, the ciphertext letter (i + s) mod 26 should appear about N·pi times. For each of the 26 candidate keys I compute Pearson's statistic

χ²(s) = Σi (O(i+s) mod 26 − N pi)² / (N pi)

and take the s with the smallest value, the shift under which the ciphertext looks most like English. Alternatives compared below:

  • most frequent letter: assume the commonest ciphertext letter is E. One count, no model.
  • χ² on letter frequencies: the algorithm above, uses all 26 frequencies.
  • exhaustive search + bigram score: decrypt with all 26 keys and keep the one with the highest log-likelihood Σ log P(xtxt+1). Uses the order of letters, not only counts.
  • exhaustive search + trigram score: the same with trigrams.

All four look at the 26 keys, the key space is so small that exhaustive search is always possible. What changes is how the right key is recognised among the 26 candidates without a human reading them.

Effect of the ciphertext length

For each length N (in letters) I take random excerpts of the test text, encrypt with a random key 1..25 and count how often each method returns the right key.

Effectiveness. With a few dozen letters the χ² method finds the key almost always. Bigram and trigram scoring need fewer letters, because they also use which letters follow which: a wrong shift quickly produces unusual pairs like "QX" or "JZ". Guessing that the most frequent letter is E is the weakest method, because in a short text E is often not the most frequent letter.

Limitations. With very short texts (one or two words) the counts are too small and several shifts look equally good; sometimes a word even decrypts to another valid word ("HAL" and "IBM" are one shift apart). The method also assumes that the language is known: a text in another language, or a list of names, can fool a model trained on English novels.

5. Attacking the toy ECC through its key space

The attacker knows the curve, G, the public key Q and the bound 2b on k. Recovering k from Q is the discrete logarithm problem, but restricted to an interval of size 2b. Two simple algorithms:

  • Exhaustive search. Compute G, 2G, 3G, … (one point addition each) until the point equals Q. Worst case 2b additions, on average half.
  • Baby-step giant-step (Shanks, 1971). With m = ⌈2b/2⌉, write k = i·m + j. Store the baby steps jG for j < m in a hash table, then walk the giant steps Q − i·(mG) until one of them hits the table. About 2·2b/2 additions and 2b/2 points of memory.

Once k is known the attacker computes S = kR and decrypts like the legitimate receiver. Note that the attack does not use the ciphertext at all: it would work before any message is sent, and the result is certain because it is checked with kG = Q.

Cost as a function of b

Why this does not work against real ECC

The attack is generic: it only uses the group operation, and its cost depends only on the size of the set the key comes from. With k uniform in [1, n − 1] and n ≈ 2256, exhaustive search needs about 2255 additions and baby-step giant-step (or Pollard's rho, the same 2128 time with no memory) about 2128. For secp256k1 no attack is known that is much faster than these generic algorithms, so with k chosen at random in the whole range the attacker needs about 2128 operations, which is not feasible. The attack works on the toy scheme only because k is restricted to a small range.

Caesar attack vs ECC attack

weakness exploited the ciphertext keeps the plaintext statistics (and the key space is tiny) only the key space is small; the ciphertext statistics give nothing
input ciphertext + language model public key Q (+ ciphertext only to read the message afterwards)

cost 26 candidates, trivial 2b or 2b/2 group operations, exponential in b

So the Caesar attack uses the statistics of the ciphertext, while the ECC attack uses only the size of the key space. A bigger key space alone would not save a letter substitution cipher (a general substitution has 26! keys and is still broken by frequency analysis), while for the ECC scheme a full-size key is enough to stop this attack.

6. Other attacks and where the weaknesses come from

From the restricted key space

  • Exhaustive search and baby-step giant-step, shown above.
  • Pollard's kangaroo method: same cost as BSGS, but almost no memory.
  • Precomputation: all keys are in the same small interval, so an attacker can compute kG for all k once and then find the private key of any user with a simple lookup.

From the design of the toy scheme

These problems would remain even with a full 256 bit private key.

  • No integrity check. Flipping a bit of c flips the same bit of the decrypted message, and the receiver cannot notice. Real ECIES adds a MAC for this.
  • The random r. If r is taken from a small range (checkbox in section 1), the same attack on R gives r and then S = rQ. If the same r is used for two messages, c1 XOR c2 = m1 XOR m2, and the two messages can be attacked statistically.
  • Message length. The ciphertext has the same length as the message, so the length is not hidden.

7. Conclusion

The Caesar ciphertext keeps the letter statistics of the plaintext, so it can be broken with statistics, and the attack works better the longer the ciphertext is. The toy ECC ciphertext looks random, so statistics do not help, but the key space is small enough to search it. The cost of that search grows exponentially with the number of key bits, which is why the real scheme with a 256 bit key is safe against it.
