Riemann vs Lebesgue integration, and the numerical normal CDF

November 2026

Exercise 1 computes the same integrals in two ways: by cutting the domain into pieces (Riemann) and by cutting the range of values into pieces (Lebesgue). Exercise 2 computes the CDF of the standard normal distribution, which has no formula in terms of elementary functions.

Exercise 1. Riemann and Lebesgue integration

1.1 The two approximations

Riemann. Divide [a, b] into N subintervals of width h = (b − a)/N and add up the areas of the rectangles. I take the value of f at the midpoint of each subinterval:

R_N = h * sum_{i=0..N-1} f(a + (i + 1/2) h)

Lebesgue. Divide the range of values [0, ymax] into M levels of height Δy. For each level, measure the set of points x where f is above that level (its preimage), and add up Δy × length of that set. This is the "layer cake" form of the Lebesgue integral of a non-negative function:

integral of f = integral_0^inf mu({x : f(x) > t}) dt L_M = dy * sum_{k=0..M-1} mu({x : f(x) > (k + 1/2) dy})

So Riemann slices the area vertically, Lebesgue slices it horizontally. To use the Lebesgue sum one needs the measure (length) μ of the sets {f > t}. For the functions of the assignment this set is an interval, so its length can be written down directly:

1.3 Comparison

Do they converge to the same value? Yes, for all the functions above both errors go to 0. This is expected: every Riemann-integrable function (and also the improper integral of 1/√x, which converges absolutely) is Lebesgue integrable with the same integral.

Accuracy and convergence. For the smooth functions (sin x, x², sin(x)/x) the Riemann midpoint error goes down by a factor 100 when N is multiplied by 10, so it is of order 1/N². The Lebesgue error goes down more slowly, about like 1/N1.5. The reason is the flat parts of f: near the maximum of sin x, or near x = 0 for x², a small interval of values corresponds to a large piece of the domain, so the function μ({f > t}) changes very quickly there (it behaves like √t) and the sum over levels is less precise. For |x − 0.5| both methods are exact, because μ({f > t}) and f are linear and the midpoint rule is exact for linear functions. For 1/√x both methods are slow (error about 1/√N), because of the singularity at 0.

Step functions. For the step functions what matters is where the cuts are. Riemann is exact when the jump at 0.5 falls on a boundary of the subintervals (N even). Lebesgue is exact when the value 1, where μ({f > t}) jumps, is a boundary between two levels: for the 0/1 step this is automatic (1 is the top of the range), for the 1/3 step it is generally not the case and the error is of order Δy (0.05 for M = 10). Lebesgue is in a sense more natural here, since a step function takes only two values and its integral is just "value × measure of the set where it takes that value".

Computational efficiency. Both sums need N (or M) terms. Riemann only needs values of f, which is always possible. Lebesgue needs the measure of the sets {f > t}, which is easy only when we can invert f. For sin(x)/x every level requires a bisection (about 60 evaluations of f), and the table above shows that it is much slower. For a general function the measure would have to be estimated by sampling the domain on a grid and counting the points above each level, which brings back a Riemann-like grid anyway. So in practice, for ordinary functions, Riemann-type rules are simpler and faster. The advantage of Lebesgue is theoretical: it can integrate functions where Riemann fails.

1.4 Pathological functions

Dirichlet function (1 on the rationals, 0 on the irrationals, on [0, 1]). Every subinterval contains both rationals and irrationals, so for every N:

Riemann sum with value for every N
rational points (e.g. the midpoints (2i+1)/(2N)) 1
irrational points (e.g. midpoint + √2/(10N)) 0
upper sum (sup of f on each subinterval) 1
lower sum (inf of f on each subinterval) 0

The sums do not converge to one value, so the function is not Riemann integrable. With Lebesgue the question is easy: f > t only on the rationals, which are countable and therefore have measure 0. So the Lebesgue integral is 0. This cannot be computed by evaluating f on a computer: every floating point number is a rational number, so a program would always find f = 1. The result comes from the measure of the sets, not from sampling f.

Thomae's function (1/q at x = p/q in lowest terms, 0 at irrationals). Here f is small at most points: only finitely many rationals have f > ε. I compute the Riemann sum exactly at the rational midpoints x = (2i+1)/(2N), using the gcd to reduce the fraction:

The sums go to 0, a bit more slowly than 1/N (the column N × sum grows slowly, like log N), and the same happens for any choice of points, so Thomae's function is Riemann integrable with integral 0. Lebesgue gives 0 directly, because f > 0 only on the rationals, a set of measure 0. Here the two approaches agree, while for the Dirichlet function only Lebesgue gives an answer.

Exercise 2. Numerical computation of the normal CDF

The CDF of the standard normal distribution is

Phi(x) = integral_{-inf}^{x} phi(t) dt, phi(t) = exp(-t^2 / 2) / sqrt(2 pi)

2.1 Why there is no elementary formula

An elementary function is one built from polynomials, exp, log, roots and trigonometric functions with a finite number of operations. The antiderivative of e−t²/2 is not one of them. This follows from Liouville's theorem (1835), in this form: if f and g are rational functions and g is not constant, then ∫ f(t) eg(t) dt is elementary only if it is of the form R(t) eg(t) with R rational. Differentiating, this means

f = R' + g' R

For our integral f = 1 and g = −t²/2, so we need a rational R with R' − tR = 1. There is none:

  • if R is a polynomial of degree d, then tR has degree d + 1 and R' has degree d − 1, so R' − tR has degree d + 1 ≥ 1 and cannot be the constant 1;
  • if R has a pole of order k at some point a, then R' has a pole of order k + 1 there, while tR has at most order k, so R' − tR still has a pole and cannot be 1.

So Φ cannot be written with elementary functions.

2.2 The error function

The way out is to give the integral a name. The error function is defined as

erf(z) = (2 / sqrt(pi)) * integral_0^z exp(-s^2) ds Phi(x) = (1 + erf(x / sqrt(2))) / 2 (substitution t = s sqrt(2))

This is an exact formula for Φ, but it only moves the problem: erf is itself defined by the integral, and to get its numerical value we still need an algorithm. It is the same situation as sin or exp: they are "known" functions, but a computer evaluates them with series or approximations. JavaScript does not even have a built-in erf, so here everything is computed by hand.

2.3 Methods

  • Trapezoidal rule on Φ(x) = 1/2 + ∫0x φ(t) dt, with n subintervals. Error of order 1/n².
  • Simpson's rule on the same integral. Error of order 1/n4.
  • Power series of erf, obtained by integrating the series of e−s² term by term:
    erf(z) = (2 / sqrt(pi)) * sum_{n>=0} (-1)^n z^(2n+1) / (n! (2n+1))
    It converges for every z. I add terms until they are smaller than 10−17 times the sum.
  • Abramowitz-Stegun 7.1.26, a closed-form approximation of erf with five constants, maximum error 1.5·10−7. It is what I used in HW4.
  • Continued fraction for the tail (Laplace), for large x:
    1 - Phi(x) = phi(x) / (x + 1/(x + 2/(x + 3/(x + ...))))
    evaluated from the bottom with 80 levels.

My method. Power series for |x| < 3, continued fraction for |x| ≥ 3, and Φ(−x) = 1 − Φ(x) for the sign. The reason for the switch is explained in 2.4.

2.4 Accuracy

The reference values are computed with mpmath.ncdf in Python with 30 significant digits; they can be checked on the web, for example on Wolfram Alpha with N[CDF[NormalDistribution[0,1], 1], 20]. Absolute errors (trapezoid and Simpson with n = 100):

Simpson is much better than the trapezoid with the same n. The series is accurate to about 10−16 for small |x|, but for large |x| it gets worse: the terms first grow (at x = 5 the largest term is about 4500) and then cancel, so digits are lost in the subtraction; at x = ±8 the error is already about 10−4. The A-S formula is fast but only accurate to about 10−7.

For negative x the absolute error is not the right measure: Φ(−5) ≈ 2.9·10−7, so an absolute error of 10−9 is already a relative error of 0.3 %. Computing Φ(−x) as 1/2 − (something close to 1/2) loses the small digits. The continued fraction computes the tail directly and keeps the relative error near 10−15, which is why I use it for |x| ≥ 3. The last column shows the relative error of my method.

2.5 Convergence of the integration rules

Doubling n divides the trapezoid error by about 4 and the Simpson error by about 16, as expected for errors of order 1/n² and 1/n4. To reach 10−10 at x = 3 Simpson needs about 150 subintervals, the trapezoid about 10000.

2.6 Efficiency

Time per evaluation, measured on 20000 evaluations at random points in [−4, 4]:

A-S is the fastest (one exponential and a few multiplications) but the least accurate. The series needs 10 to 35 terms for |x| < 3, and the continued fraction 80 divisions, both still much faster than Simpson with n = 100, which needs 101 exponentials. So the series plus continued fraction is both accurate and cheap.

2.7 Conclusion

The normal CDF has no elementary formula (Liouville), erf gives it a name and an exact representation, but the numbers still come from a numerical method. Integration rules work but need many evaluations of the exponential; the power series is the best choice near the centre, and a separate method for the tails is needed if small probabilities like Φ(−5) must be computed with good relative accuracy, which is the case in statistical tests with small p-values.
